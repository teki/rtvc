# C80 Language Reference

> **Work in progress:** C80 is experimental. The language, ABI, and output
> formats may change without notice, and it has not yet been used for real
> programs beyond its own tests and tutorial examples.

This page describes what the compiler does today. Every C80 code block on
it is compiled by [docs.rs](../c80/tests/docs.rs), and a block that shows a
rejected form is checked to give the stated diagnostic codes. The
[C80 Tutorial](c80/tutorial.md) walks through the same features with
example files.

## Overview

C80 is a small C-like language for Z80 programs in rtvc. It is not ISO C:
there is no heap, no recursion, no implicit integer promotion, and no `*`,
`/`, or `%`. It is meant as an alternative to a macro assembler, and the
generated code is judged against hand-written Z80. Values live in registers
first. Spill code and costs are visible in the listing.

The compiler is the `rtvc-c80` crate in [`c80/`](../c80/). `cargo build` in
the repository root does not build it; use `cargo run -p rtvc-c80`. Native
desktop, `wasm-full`, and the lightweight `wasm` build of `rtvc` do not
include it, and there is no editor integration.

The compiler works on in-memory source snapshots. It returns the parsed
units, located diagnostics, typed IR, assembled Z80, a listing map, and
optional tokenized BASIC. It does not read the filesystem; the CLI does that.
Code is assembled with the repository's helper assembler
([asm.rs](../src/emulator/asm.rs)), and addresses come from the assembler,
not from parsing disassembly.

```c80
u8 id(u8 x) { return x; }               // RET
u16 add(u16 a, u16 b) { return a + b; } // ADD HL,DE / RET
```

## Lexical Form

- Source is UTF-8. Spans are byte offsets (start inclusive, end exclusive),
  shown as 1-based lines and byte columns.
- Identifiers are ASCII letters, digits, and `_`, starting with a letter or
  `_`. They are case-sensitive.
- Keywords: `void`, `bool`, `u8`, `i8`, `u16`, `i16`, `str`, `ptr`, `true`,
  `false`, `pub`, `const`, `static`, `import`, `struct`, `if`, `else`,
  `while`, `for`, `do`, `return`, `break`, `continue`, `sizeof`, `asm`.
- Comments: `// line` and non-nested `/* block */`. A comment line that
  starts with `//!` is an ordinary comment to the compiler; the example tests
  read it (see [Testing](#testing)).
- Integers are decimal or hexadecimal with a `0x`/`0X` prefix (`0xFE`).
  There are no binary or octal literals and no digit separators. A literal
  must fit in 32 bits before typing.
- Character literals `'A'` and string literals `"hello"`. Escapes: `\n`,
  `\r`, `\t`, `\0`, `\\`, `\'`, `\"`, and `\xNN` (exactly two hex digits).
  Other escapes and non-ASCII bytes in literals are errors.

## Grammar

```text
unit        := { item }
item        := import | struct | function | global
import      := "import" ident ";"
struct      := "struct" ident "{" { field } "}" ";"
field       := type ident [ "[" expr "]" ] ";"
function    := { attr } [ "pub" ] { attr } type ident "(" [ params ] ")" block
params      := param { "," param }
param       := type ident [ pin ]
pin         := "@" register
global      := [ "pub" ] [ "const" ] type ident [ "[" expr "]" ] [ "=" expr ] ";"
type        := "void" | "bool" | "u8" | "i8" | "u16" | "i16" | "str"
             | "ptr" "<" type ">" | ident
attr        := "@fastcall" | "@stackcall"
             | "@preserves" "(" register { "," register } ")"
             | "@inline" | "@noinline"
register    := a | b | c | d | e | h | l | bc | de | hl

block       := "{" { stmt } "}"
stmt        := block
             | [ "const" ] type ident [ "[" expr "]" ] [ pin ] [ "=" expr ] ";"
             | "static" type ident [ "[" expr "]" ] [ "=" expr ] ";"
             | "if" "(" expr ")" stmt [ "else" stmt ]
             | "while" "(" expr ")" stmt
             | "for" "(" [ local-or-expr ] ";" [ expr ] ";" [ expr ] ")" stmt
             | "do" stmt "while" "(" expr ")" ";"
             | "return" [ expr ] ";"
             | "break" ";"
             | "continue" ";"
             | asm-stmt
             | expr ";"
asm-stmt    := "asm" [ "(" clause { "," clause } ")" ] "{" assembly-text "}"
clause      := "in:" register "=" expr
             | "out:" ( register | "carry" | "zero" ) "=" lvalue
             | "inout:" register "=" lvalue
             | "clobber:" ( register | "flags" | "memory" ) { "," ... }
             | "stack:" integer

expr        := assign
assign      := or [ ( "=" | "+=" | "-=" | "&=" | "|=" | "^=" | "<<=" | ">>=" ) assign ]
or          := and { "||" and }
and         := bitor { "&&" bitor }
bitor       := bitxor { "|" bitxor }
bitxor      := bitand { "^" bitand }
bitand      := eq { "&" eq }
eq          := rel { ( "==" | "!=" ) rel }
rel         := shift { ( "<" | "<=" | ">" | ">=" ) shift }
shift       := add { ( "<<" | ">>" ) add }
add         := prefix { ( "+" | "-" ) prefix }
prefix      := ( "+" | "-" | "!" | "~" | "*" | "&" | "++" | "--" ) prefix | postfix
postfix     := primary { "(" args ")" | "[" expr "]" | "." ident | "->" ident
                       | "::" ident | "++" | "--" }
primary     := ident | integer | character | string | "true" | "false"
             | "(" expr ")"
             | type "(" expr ")"            # conversion: u8(x), ptr<u8>(a)
             | "sizeof" "(" type ")"
             | "{" [ expr { "," expr } [ "," ] ] "}"   # initializers only
args        := [ expr { "," expr } ]
```

Attributes may stand before or after `pub`. The grammar accepts a few forms
that the type checker rejects with a located error: an automatic local array
or struct, a pin on a `const` or `static`, `static` at file scope or in a
`for` initializer. A comma after `clobber:` names starts a new clause when the
next token is a clause keyword and a colon. Asm header names are lowercase.

The parser recovers at `;`, `}`, and the start of the next top-level
declaration, so later functions are still checked after a broken one.

## Types and Conversions

| Type | Size | Notes |
| --- | --- | --- |
| `bool` | 1 | `false` is 0, `true` is 1 |
| `u8`, `i8` | 1 | signedness is interpretation only |
| `u16`, `i16` | 2 | little-endian |
| `ptr<T>` | 2 | `T` is `bool`, an integer, a struct, or a pointer |
| `str` | 2 | a reference to a length byte plus payload |
| `struct S` | sum of fields | packed, declaration order, no padding |
| `T name[N]` | `N * sizeof(T)` | globals and `static` locals only |

- Operands of a binary operator must have the **same** type after literals
  are typed; `u8 + u16` is an error. Convert explicitly.
- An untyped literal takes the type its context needs (assignment, return,
  argument, the other operand) if it fits; otherwise it is
  `ty-literal-range`. A literal-only expression with no context is `u16`, or
  `i16` if it contains a negative literal. `-32768` is a valid `i16`.
- A conversion `T(x)` types `x` on its own, then converts: same width keeps
  the bits, narrowing keeps the low bits, widening sign- or zero-extends by
  the source type. `bool(n)` is `n != 0`; `u8(true)` is 1. `bool b = 1;` is
  an error; write `bool(1)` or `true`.
- `ptr<U>(p)` reinterprets a pointer; `ptr<u8>(addr)` and `u16(p)` convert
  between pointers and `u16`.
- `sizeof(T)` is a `u16` constant for scalars, pointers (2), `str` (2), and
  named structs. `sizeof(void)` and `sizeof` of an array type are errors.
- Conditions (`if`, `while`, `for`, `do`, `!`, `&&`, `||`) must be `bool`.

```c80
u16 widen(i8 x) { return u16(i16(x)); }   // sign-extends, then keeps the bits
u8 low(u16 w) { return u8(w); }
bool nonzero(u8 x) { return bool(x); }
```

```c80 error=ty-mismatch
u16 f(u8 a, u16 b) { return a + b; }
```

```c80 error=ty-mismatch
u8 f(u8 x) { if (x) { return 1; } return 0; }
```

## Expressions and Operators

Precedence, weakest first: assignment; `||`; `&&`; `|`; `^`; `&`;
`==` `!=`; `<` `<=` `>` `>=`; `<<` `>>`; `+` `-`; prefix; postfix (call,
index, member). Assignment and prefix operators are right-associative, the
rest left-associative. As in C, `+` binds tighter than a shift:
`a << b + c` is `a << (b + c)`.

- **Arithmetic.** `+` and `-` wrap at the operand width (`u8 x = 255 + 1` is
  0). Unary `-` and `~` work on integers.
- **Bitwise.** `&`, `|`, `^` on integers of one type.
- **Comparisons** give `bool`. Ordered compares need the same integer type
  and are signed on `i8`/`i16`. Pointers allow `==` and `!=` only.
- **Short-circuit.** `&&` and `||` evaluate the right operand only when
  needed; a skipped operand performs no load, store, call, or port access.
  Used as a condition, `&&`, `||`, `!`, and comparisons are branches; used
  as a value, the result is built as 0 or 1.
- **Assignment** is an expression whose value is the stored value.
  Compound `+= -= &= |= ^= <<= >>=` evaluate the destination address once,
  read, evaluate the right side, and write once. On pointers only `+=` and
  `-=` are allowed, stepping whole elements.
- **`++` and `--`** work on integer and pointer lvalues. Prefix gives the new
  value, postfix the old one.
- **Pointer arithmetic.** `p + n` and `p - n` scale by `sizeof(T)` and wrap
  in the 16-bit address space. There is no pointer subtraction.
- **Order.** Arguments and operands are evaluated left to right, once.
  Every load and store of a global, a `static`, or memory through a pointer
  is performed as written: repeated reads are not merged and successive
  writes are not coalesced.

### Shifts

- `x << n` and `x >> n` take any integer `x` and a `u8` count; the result has
  `x`'s type. An untyped literal count is a `u8`; a typed count of another
  type is `ty-mismatch` ("shift count must be u8, found u16"). `bool` and
  pointers do not shift.
- `<<` drops the bits that leave the type. `>>` is logical on `u8`/`u16` and
  arithmetic on `i8`/`i16`.
- A count at or above the width is defined, not masked: the result is 0, or
  all sign bits for a negative signed `>>`. `u8 x >> 9` is 0.

Constant counts use the fastest of several sequences (T-states first, then
bytes): `ADD A,A` (4 T) and `ADD HL,HL` (11 T) per step left, `SRL`/`SRA`
(8 T) per step right, rotate-and-mask (`u8 << 6` is
`RRCA / RRCA / AND 192`), byte moves for word counts of 8 or more, the
opposite shift with the leaving bits caught in `A` for word counts 5 to 7,
and a sign fill for `i8 >> 7` and `i16 >> 15`. Sequences that need `A` as
scratch are used only when `A` holds nothing live. The examples in
[shifts.c80](c80/shifts.c80) pin their costs with `expect-tstates` lines.

A variable count copies the count to `B` (or another free register), skips
the loop when it is zero, and repeats one step with `DJNZ`
(`DEC r / JR NZ` outside `B`). Counts above the width run all their steps
(at most 255); the result is still the defined one, but the time grows with
the count.

A shift whose result goes back to the register its operand came from
(`x <<= 1` with `x @ b`) runs there (`SLA B`) when that is no slower. Shifts
of memory operands (globals, `static`s, fields, through pointers) load,
shift in registers, and store.

```c80
u8 times64(u8 x) { return x << 6; }
i16 sign16(i16 x) { return x >> 15; }
u16 var_shift(u16 x, u8 n) { return x >> n; }
```

```c80 error=ty-mismatch
u8 f(u8 x, u16 n) { return x << n; }
```

## Statements

- **Locals** have no implicit value. A read must be preceded by an
  assignment on every path, including an `if` without `else` and a `while`
  that may run zero times (`ty-use-before-assign`, reported once per local
  and function). Parameters are assigned. `const` locals need a compile-time
  initializer and have no storage.
- **Scopes.** An inner block may shadow an outer name; a duplicate in one
  scope is `ty-duplicate-name`.
- **`if`/`else`, `while`, `do ... while`, `for`.** `for (init; cond;
  update)` with an empty `cond` loops forever; `continue` runs `update`, then
  the condition. `do` runs its body once before the first test; `continue`
  in it goes to the condition. `break` and `continue` outside a loop are
  errors.
- **`return`.** Every reachable exit of a non-`void` function returns a
  value (`ty-missing-return`). A `void` function may fall off its end.
- **Expression statements** may discard any value, including `cpu::in`.

```c80
u8 count_set(u8 x) {
    u8 n = 0;
    while (x != 0) {
        if ((x & 1) != 0) { n += 1; }
        x >>= 1;
    }
    return n;
}
```

```c80 error=ty-use-before-assign
u8 f(bool c) {
    u8 x;
    if (c) { x = 1; }
    return x;
}
```

## Data

### Globals and source order

Globals are placed with the functions in source order, not in a separate
section. A global without an initializer is zero in the image. A `const`
global has no storage; a `pub const` is visible to other units and to BASIC
markers. A data-only unit keeps its declaration order.

### Arrays

`T name[N]` declares a one-dimensional array of scalars or complete structs,
`N` from 1 to 65535 and at most 65535 bytes in total. Only globals and
`static` locals can be arrays. Arrays do not decay: write `&a[0]`, not `a`.
`a[i]` with a constant `i` outside the array is an error; a variable index
is not checked. Whole-array assignment is rejected. Index scaling is shifts
and adds (`(i << 2) + i` for a 5-byte element), not a multiply.

### Pointers

`ptr<T>` is a 16-bit address. `&x` is allowed on a scalar global, a `static`,
an unpinned local (which then lives in a static slot), a field, and an array
element. `&array` without an index, the address of a constant, of a string
payload, of a function, or of a pinned local are errors. Returning `&local`
directly is the warning `ty-return-local-addr`: the local's slot is reused
by the next call.

### Strings

A `str` global owns a length byte and a payload of 0 to 255 bytes and needs
a string-literal initializer. `str` locals, parameters, and returns are
2-byte references. `s.len` is a `u8`; `s[i]` reads the payload at
`s + 1 + i` (a constant index is checked when the length is known). Owned
payloads are immutable. A literal passed to a `str` parameter is placed
after the calling function.

### Structs

Structs are packed in declaration order with no padding: `struct Sprite {
u8 x; u8 y; u16 bitmap; bool visible; };` is 5 bytes. Fields may be
scalars, pointers (including `ptr<Self>`), nested structs, or fixed arrays
of those. `str` fields, empty structs, and recursive by-value layouts are
errors. `.` and `->` give ordinary lvalues. Structs are not passed or
returned by value; pass a pointer.

### Static initializers and addresses

A global or `static` initializer is a compile-time value: a constant
expression, a string literal, or a brace list (positional, nestable,
trailing elements zero). Too many initializers is an error.

An initializer may also hold an address fixed at link time:

- `&global`, `&array[K]`, `&global.field`, `&array[K].field`, and deeper
  `.field`/`[K]` chains, with `K` a constant inside the array;
- the same through another unit: `&unit::global`, `&unit::array[K]`;
- wrapped in `ptr<U>(...)` or `u16(...)`.

The value is typed like the same `&` in code, so `u16 x = &g;` is a
`ty-mismatch` (write `u16(&g)`). Forward references within a unit are
allowed; a struct may point at itself. The word is emitted as `DW label` or
`DW label+offset`, resolved by the assembler across unit segments, and
listed in `CompilerMap::data_refs`.

Rejected: `&array` without an index, a constant index outside the array, a
non-constant index, indexing a pointer, an automatic or pinned local in a
`static` initializer, a `const` holding an address (a const is folded; the
address exists only at link time), and arithmetic on an address such as
`&a[1] + 1` (write `&a[2]`).

```c80
struct Node { u8 value; ptr<Node> next; };
Node first = { 1, &second };
Node second = { 2, &first };
u8 frames[8];
ptr<u8> mid = &frames[4];
u16 rows[2] = { u16(&frames[0]), u16(&frames[4]) };
```

```c80 error=ty-mismatch
u8 g;
const ptr<u8> p = &g;
```

## Functions

### Calling conventions

| Convention | Arguments | Result | Frame |
| --- | --- | --- | --- |
| default (register) | words: `HL`, `DE`, `BC`; then bytes and `bool`: `A`, `C`, `B`, `E`, `D`, `L`, `H`, skipping halves used by words | byte in `A`, word in `HL` | none |
| `@fastcall` | as default | as default | none; body must fit in registers |
| `@stackcall` | two-byte slots, pushed right to left, removed by the caller | as default | `IX` frame for parameters only |

A signature that does not fit in registers is `cg-unsupported`
("use explicit @stackcall"); the compiler never adds hidden stack arguments.
A `@stackcall` function saves `IX` and reads its parameters from `IX+4`
onward; the last byte must be within `IX+127`. No other function uses `IX`.

Direct and mutual recursion (also across units) is `ty-recursion`: static
slots and `static` locals have fixed addresses, so C80 code is not
reentrant.

```c80
@stackcall u16 sum4(u16 a, u16 b, u16 c, u16 d) { return a + b + c + d; }
u16 use_sum4() { return sum4(1, 2, 3, 4); }
```

```c80 error=cg-unsupported
u16 f(u16 a, u16 b, u16 c, u16 d) { return a; }
```

### Strict `@fastcall`

`@fastcall` keeps the register convention and requires the body to use
registers only: no static slot, no `PUSH`/`POP` save, no `IX`, no
`INC SP`/`DEC SP`. Return addresses are the only stack use. Anything else is
a located `cg-unsupported` error that names the value and the operation and
ends "pin values to free registers, declare a local 'static', or remove
@fastcall". A register-to-register move marked `; spill` is allowed. A value
live across a call must sit in a register the callee's contract preserves;
otherwise the error names the registers it does preserve, or suggests
`@preserves` on a callee without a contract.
`GeneratedFunction::strict_registers` records the attribute.

### Register pins

`type name @ reg` on a parameter or an automatic local fixes its register:
bytes to `a b c d e h l`, words and pointers to `bc de hl`. The scope is the
whole function for a parameter, and from the initializing store (or the
declaration) to the end of the block for a local.

- A pin is never moved, spilled, or shared while in scope.
- A store into the pinned value may compute the new value in the pin's
  register when the old value is dead (`s = s + a` with `s @ hl` is one
  `ADD HL,DE`).
- A pinned parameter that arrives in another register costs one entry move.
- An operation that needs the pinned register for something else is a
  `cg-unsupported` error ("'s' is pinned to hl, but the u16 `+` needs hl for
  something else; ..."), never a hidden move.
- Across a call or another operation that clobbers it: a marked `PUSH`/`POP`
  in a default function, an error in a `@fastcall` one.
- Errors before code generation: a width mismatch or pinned `const`
  (`ty-mismatch`), two pins on one register in one scope
  (`ty-duplicate-name`; disjoint blocks may share), `&` of a pinned value
  (`ty-not-lvalue`), and an unknown register.

```c80
@fastcall u8 times(u8 n @ b, u8 step) {
    u8 total = 0;
    do { total += step; n -= 1; } while (n != 0);
    return total;
}
```

```c80 error=ty-not-lvalue
ptr<u8> f() { u8 n @ b = 3; return &n; }
```

### `static` locals

`static type name [ "[" N "]" ] [ = init ];` inside a function declares
storage placed right after the function (after its slot area). It is zero or
its initializer in the image, keeps its value between calls, is always
assigned, and has an address. Every access is a real load or store. Arrays
and structs are allowed, and this is how a function gets a local array.
`static` is reported as a global named `function.name`. It is rejected at
file scope, in a `for` initializer, with `const`, with a pin, and with a
non-constant initializer ("a static initializer must be a compile-time
value"). A static initializer may take the address of a global or of
another `static` in scope.

```c80
u8 next_id() {
    static u8 counter = 0;
    static u8 squares[4] = { 0, 1, 4, 9 };
    counter += 1;
    return squares[counter & 3];
}
```

```c80 error=ty-mismatch
u8 f(u8 x) { u8 buf[4]; buf[0] = x; return buf[0]; }
```

### Register contracts

A function's contract is the set of registers it returns unchanged. A call
clobbers the callee's other registers plus its argument and result
registers; a caller keeps values in the rest at no cost.

- **Declared.** `@preserves(bc, de)` with pin register names; halves and
  pairs mean the same (`b, c` is `bc`). The body never uses a preserved
  register; an operation that needs one is a `cg-unsupported` error at that
  statement. A call or `asm` block that may change one is wrapped in a
  marked `PUSH`/`POP` (default function) or is an error (`@fastcall`).
  Errors: a result register in the list, a pin on a preserved register, an
  empty list, an unknown name, a second `@preserves`, `@preserves` on a
  non-function.
- **Inferred.** A function that is not `pub` and has no `@preserves`
  promises the registers its final code never writes (calls count their
  callee's clobbers; `asm` its declared inputs, outputs, and clobbers).
  Inference never crosses units. A `pub` function without `@preserves` has
  no contract, so editing it cannot change code in another unit.
- `GeneratedFunction::preserves` and `contract` (`Declared`, `Inferred`,
  `None`) report it. The test harness checks every contract at run time.

```c80
@preserves(bc) u8 bump(u8 x) { return x + 1; }
u8 caller(u8 a, u8 b) {
    u8 y = bump(a);    // b stays in a register across the call
    return y + b;
}
```

```c80 error=cg-unsupported
u16 total;
@preserves(hl) void acc(u16 a, u16 b) { total = a + b; }
```

### Inlining

**`@inline`** expands every C80 call to the function in place, in both
optimized and `--no-optimize` builds; it is a guarantee, not a hint. It
combines with `@fastcall` and `@preserves`; `@inline @stackcall`,
`@inline @noinline`, and a repeated attribute are `parse-expected` errors.

- Semantics are the call's: arguments are evaluated once, left to right; each
  parameter is a fresh local (read directly when the body never writes it);
  a constant argument becomes an immediate; each `return` continues after
  the call.
- A private `@inline` function has no out-of-line copy; `pub @inline` keeps
  one for BASIC markers and ASM units. `static` locals are shared by all
  expansions. Inline `asm` gets a fresh label namespace per copy.
- The expansion is the caller's code: the caller's allocator, `@preserves`,
  and strictness apply to it. A diagnostic inside it ends "(in 'g', inlined
  into 'f')" with the call sites as related spans. A pin in the body that
  overlaps a caller pin or preserved register live at the call is a
  `ty-duplicate-name` error at the call.

**Automatic inlining** (optimized builds only) expands a call to a private
function that is not `@inline`, `@noinline`, or `@stackcall` and has no
`asm` with `CALL`/`RST`, when a trial lowering shows no new spill and either
the caller does not grow, or the callee has exactly one call and the caller
grows by at most the callee's body. A private function left with no call
emits no body. **`@noinline`** opts a function out.

Each expansion starts with `; inline NAME` (or `; inline NAME (auto)`) in
the listing; `MappedInstruction::inlined` lists the call frames and
`GeneratedFunction::inlined` each expanded call. `compile_keeping_bodies`
also emits the bodies of fully inlined functions so a test can call them.

```c80
@inline u8 col(u8 x) { return x >> 2; }
u8 cols(u8 a, u8 b) { return col(a) + col(b); }
```

```c80 error=parse-expected
@inline @stackcall u8 framed(u8 x) { return x; }
```

## Where Values Live

Locals, temporaries, and parameters live in registers whenever they can.
A fallback is used only where a value must survive a call, `cpu::ldir`, or an
`asm` block that clobbers its register, or where more values are live than
registers. The compiler picks the cheapest fallback by estimated T-states,
counting loop bodies eight times:

| Fallback | Save + restore |
| --- | --- |
| Move to a register the operation leaves alone | 8 T |
| `PUSH rr` / `POP rr` around the operation | 21 T |
| Byte in a static slot, `LD (nn),A` / `LD A,(nn)` | 26 T |
| Word in a static slot through `HL` | 32 T |
| Word in a static slot through `BC`/`DE` (ED forms) | 40 T |

A value in `A` that must survive a push also moves to a free half of the
pushed pair (4 T) or uses `PUSH AF`.

**Static slots** are bytes in a zero-filled area right after the function's
code (`LABEL_S: DB 0,...`). They hold values evicted when more are live
than registers (the one used farthest ahead goes), locals with no register
home, and address-taken locals (`&x` is `LD HL,LABEL_S`). Slots are reused
once their value dies, so the area is as large as the peak need. Slot bytes
count in the function's size and are linked like code. They make functions
non-reentrant, which C80 accepts because it has no recursion.

**Homes.** A function with branches gives each local one home. Several home
plans are lowered (every local in a register; `HL` kept free with `BC`/`DE`
for the most used locals; a pointer in `BC`/`DE` with `HL` left to a word
accumulator) and the cheapest estimate wins.

**Stack bounds.** Each function reports a bound: the `@stackcall` frame
plus the larger of its own peak pushes and its worst call site (pushes below
the return address, the `CALL`, and the callee's bound). Static slots do not
count. A bound is `proven` (C80 code), `declared` (a trusted `stack:N` or an
ASM unit's `stack_extra`), or `unknown` (an `asm` `CALL`/`RST` without
`stack:N`).

**Reading the listing** (`--emit-asm`):

- `; spill` marks every fallback instruction. These and the slot `DB` are
  `synthetic` in the listing map.
- `; spill report: N slot bytes, saves (bytes per site) ..., T T-states of
  spill code` ends a function with fallbacks (a static sum of its `; spill`
  lines; also `GeneratedFunction::spill`).
- `; preserves B C (declared)` or `(inferred)` ends a function with a
  declared contract, or an inferred one that a caller uses.
- `; inline NAME` and `; inline NAME (auto)` start an expansion.

If an overwrite of a live value survives code generation anyway, the
compiler reports `cg-internal` at the statement instead of emitting the code.

## Inline Assembly

`asm { ... }` is a statement. Without a header it clobbers `AF`, `BC`, `DE`,
`HL`, and memory. With a header:

- `in: r = expr` loads a register before the body; `out: r = lvalue` stores
  it after; `inout: r = lvalue` does both and needs a prior assignment;
- `out: carry = b` and `out: zero = b` capture a flag as `bool`;
- `clobber:` lists registers, `flags`, and `memory`;
- `stack:N` is a trusted extra-stack bound for the body.

Register width must match the operand: bytes and `bool` for `a`..`l`;
words, pointers, and `str` for `bc`/`de`/`hl`. Overlapping inputs or
overlapping outputs are errors; an input may reuse an output register; a
clobber may not overlap an output (`flags` may coexist with `carry`/`zero`).
Header expressions and destination addresses are evaluated once, left to
right, before the body. `bool` register outputs are normalized to 0 or 1.

The body is [helper assembler](assembler.md) text, including `$` and `;`
comments. Allowed: instructions, local labels (namespaced per block), local
`EQU`, balanced `PUSH`/`POP`, and returning `CALL`/`RST`. Rejected: `RET`,
`RETI`, `RETN`, jumps out of the block, indirect jumps, `ORG`,
`BASIC_START`, `DB`/`DW`/`DS`, `SP` changes, and `IX`/`IY`/`EXX`/`EX AF`
writes other than balanced `PUSH`/`POP IX`/`IY`. A visible stack peak above
`stack:N` is an error; `CALL`/`RST` without `stack:N` warns (`ln-stack`)
and makes the stack bound unknown. A `@{unit::export}` marker in a body is a
`cg-unsupported` error. `asm` at file scope is `parse-unsupported`.

```c80
u8 add_carry(u8 left, u8 right) {
    u8 sum;
    bool carry;
    asm (in: a = left, in: b = right, out: a = sum, out: carry = carry, clobber: flags) {
        add a, b
    }
    if (carry) { return sum + 1; }
    return sum;
}
```

## CPU Builtins

`cpu::in(u8 port) -> u8`, `cpu::out(u8 port, u8 value)`, `cpu::di()`,
`cpu::ei()`, and `cpu::ldir(src, dst, count)` are intrinsics in the reserved
`cpu` namespace. They are not imported and cannot be used as values. Bare
`in`, `out`, `di`, `ei`, `ldir` are ordinary names.

- Each `cpu::in`/`cpu::out` transfers one byte and is always performed: never
  folded, merged, removed, or moved, including a discarded `cpu::in` and
  repeated identical writes. A typed `u16` port or value needs `u8(...)`.
- On target `tvc` a constant port is `IN A,(n)` / `OUT (n),A` and a variable
  port uses `(C)` without forcing `B`. On `generic-z80` and `zx82` the port
  is zero-extended into `BC` and the `(C)` forms are used.
- `cpu::di()` and `cpu::ei()` emit `DI` and `EI`.
- `cpu::ldir(hl, de, bc)` is raw `LDIR`: **HL is the source, DE the
  destination, BC the count** (the reverse of `memcpy`). Source and
  destination are pointers or `u16`/`i16`; the count is `u16`. `BC = 0`
  copies 65536 bytes. It clobbers `HL`, `DE`, `BC`, the flags, and memory.

```c80
u8 read_row(u8 row) {
    cpu::out(0x03, row);
    return cpu::in(0x58);
}
void copy_block(ptr<u8> src, ptr<u8> dst, u16 n) { cpu::ldir(src, dst, n); }
```

## Units, Manifests, and Mixed BASIC Projects

A project is a TOML manifest listing units:

```toml
version = 1
target = "generic-z80"      # or "tvc", "zx82"

[stack]
base = 0xFF00
size = 0x0100               # optional interrupt_allowance = N

[[unit]]
name = "math"
path = "math.c80"
origin = 0x2100             # needed when the unit emits bytes

[[unit]]
name = "boot"
kind = "asm"
path = "boot.asm"
origin = 0x2000
exports = ["start"]
stack_extra = 16
```

- **Imports.** `import other;` then `other::name` reaches **public**
  symbols of a C80 unit. Unqualified names stay local. A missing unit, a
  missing import, and a private name are `ty-unresolved-name`. `project` and
  `cpu` are reserved namespaces.
- **Constants.** `pub const` has no storage. A constants-only unit needs no
  origin and emits nothing; list it before the units that import it.
- **Layout.** Each emitting unit starts at its own `ORG` and keeps its
  declaration order. Optional `[[reserve]]` entries (`name`, `base`, `size`)
  occupy no bytes. Ranges may touch but must not overlap (`ln-overlap`) or
  pass 65536.
- **Stack.** `project::stack_base`, `stack_size`, `stack_top`
  (`(base + size) mod 65536`), and `stack_end` are compile-time `u16`
  values when a `[stack]` table exists. The largest C80 stack bound plus the
  largest ASM `stack_extra` plus `interrupt_allowance` must fit in `size`
  (`ln-stack`); an ASM unit without `stack_extra` makes the check a warning.
- **ASM units** have no prologue. `@{unit::export}` and `@{project::name}`
  are substituted outside quotes and comments. `exports` lists the labels
  other units may use; private labels are namespaced, and case-insensitive
  collisions are errors. C80 cannot call an ASM export: importing an ASM
  unit is an unknown unit.
- **BASIC** (target `tvc` only). A `[basic]` table with a `path` adds a
  BASIC program, tokenized and stored at `19EFH`. It must not overlap any
  other range. C80 may read `project::basic_base`; `basic_size`,
  `basic_end`, `basic_himem`, and `basic_program_size` exist only after
  tokenization and are not C80 values. In the BASIC source,
  `@{unit::export}` and `@{project::symbol}` become unsigned decimal
  numbers, except inside strings, `REM`/`!` tails, and `DATA` fields (an
  unquoted `DATA` colon resumes substitution). A `pub const` becomes its
  value. The compiler does not write interpreter state or generate `USR`
  wrappers. A typical entry is `LET R=USR(@{math::echo},42)` with
  `@fastcall pub i16 echo(i16 value)`: the argument and result are in `HL`.

`rtvc-tocas` turns a mixed `rtvc-asm-v1` TOML whose first segment is
BASIC at `19EFH` into one cassette (gaps zero-filled, end at most `C000H`)
with the autostart byte set; `rtvc -i` then types `RUN`.

## CLI and Outputs

```text
rtvc-c80 build INPUT [--target TARGET] [--origin ADDRESS] [--no-optimize]
                     [--emit-asm PATH] [--emit-segments PATH] [--emit-bin PATH]
```

The CLI is [rtvc_c80.rs](../c80/src/bin/rtvc_c80.rs). At least one output is
required. A `.c80` input is a single unit named after its stem (so the stem
must be an identifier) and needs `--origin` when it emits bytes; `--target`
defaults to `generic-z80`. A `.toml` input is a manifest; paths resolve from
its directory, and `--origin` is invalid.

- `--emit-asm`: the listing, with the annotations described under
  [Where Values Live](#where-values-live). A mixed project appends
  `ORG`/`DB` lines for the BASIC bytes.
- `--emit-segments`: `rtvc-asm-v1` TOML with every segment, `[symbols]`,
  and, for a BASIC project, the tokenized payload and
  `project::basic_program_size`.
- `--emit-bin`: raw bytes; the emitted ranges must be contiguous and are not
  padded.

Diagnostics print as `path:line:col: severity code: message`, then the
source line and a `^~~~` underline; related spans follow as indented
`path:line:col: note: ...` lines. Columns are 1-based byte columns.
`render_diagnostic` produces the same text.

**Maps.** `CompilationResult::map()` (in process only; there is no
`--emit-map`) has listing entries (address, bytes, text, timing, kind,
spans), symbols, no-code spans, static address words (`data_refs`), stack
provenance, and a build identity. Timing is `Exact`, `Branch`
(taken/not-taken), `Repeating`, or `Unknown`, from the disassembler's data
on the final bytes. `SpanCost` is not `complete` when the span contains a
call, a loop, a repeating instruction, or unknown timing. A failed compile
has no code and no map.

## Optimization

`compile_source`, `compile`, `compile_project`, and the CLI optimize by
default. `--no-optimize` (or `optimize: false`) is the plain baseline: all
jumps `JP`, no fallthrough removal, no folding, no automatic inlining. Both
modes must give the same results, memory and port traces, and stack
balance; the conformance suite, the examples, and the TVC tests run in both.

Both modes:

- `&&`, `||`, `!`, and comparisons in a condition are branches, not 0/1
  values;
- a byte load or store through a pointer already in `BC`/`DE` is
  `LD A,(BC)` / `LD (DE),A`, and `p = p + 1` (or `+ 2`) into a `BC`/`DE`
  home is `INC rr`;
- a byte `x = x + 1` or `x - 1` in `x`'s register is `INC r` / `DEC r`;
- `@inline` expansion.

Optimized builds also run, in order:

1. **Unreachable IR blocks** (no path from the entry) are dropped.
2. **Automatic inlining** (see [Inlining](#inlining)).
3. **Constant folding** of literal-only expressions with C80's wrapping,
   shift, and signedness rules (`(1 << 5) - 1` is `LD A,31`); a branch on a
   constant becomes a jump.
4. **Peepholes**, each gated on backward register and flag liveness:
   `CP 0` to `OR A`; `ADD A,1`/`SUB 1` to `INC A`/`DEC A` when carry is
   dead; `LD A,0` to `XOR A` when all flags are dead; `ADD A,0` removed; a
   word add of `k * 256` on the high byte only; `x + x` to `ADD HL,HL`; a
   register load nothing reads removed (`RET` reads only the result and the
   preserved registers).
5. **Register tracking** in straight-line code: a reload of a constant, an
   address, or a compiler slot already held in a register becomes a
   register move or disappears. Globals, `static`s, pointer targets, and
   ports are always re-read.
6. **Control flow:** jumps to jumps go to the final target, unreachable code
   and jumps to the next label are dropped, `JP cc,then / JP else` with
   `then` next becomes `JP !cc,else`.
7. **Loop rotation:** a `while` loop's entry jumps to the test at the
   bottom, so each pass ends with one conditional branch. A loop that runs
   zero times costs 10 T more than unrotated, one pass 3 T more; every
   further pass saves 7 T.
8. **`DJNZ`** closes a loop whose counter is in `B` when `A` and all flags
   are dead after the test: a `do` loop that decrements the counter just
   before `while (n != 0)`, or a rotated `while (n != 0)` whose own guard
   then runs once at the entry, so `n == 0` still skips the loop. Other
   counters keep `DEC r` / `JP NZ`.
9. **Tail calls:** `CALL f` directly followed by `RET` becomes `JP f`. In a
   single-file build the stack bound is recomputed (the call adds the
   callee's bound, not 2 more bytes); project builds keep the larger bound.
10. **`JR`:** after layout, a forward `JP Z/NZ/C/NC` whose displacement
    fits becomes `JR`. Backward and unconditional jumps stay `JP`: a taken
    `JR` costs 12 T against 10 T for `JP`, and a loop edge is usually taken.

No pass merges or removes accesses to memory or ports. Every pass keeps
source provenance: a merged instruction keeps all its origins, a removed one
leaves a no-code mapping, and the listing map covers every byte.

## Limits and Diagnostics

### Not supported

Each of these is rejected with a located diagnostic.

| Form | Code | Instead |
| --- | --- | --- |
| `*`, `/`, `%`, `*=`, `/=`, `%=` | `parse-unsupported` | shifts and adds |
| automatic local arrays and structs | `ty-mismatch` | `static`, a global, or a pointer |
| recursion, direct or mutual | `ty-recursion` | a loop |
| by-value struct parameters and returns | `ty-mismatch` | pass a pointer |
| whole-array assignment | `ty-not-lvalue` | a loop or `cpu::ldir` |
| arrays of pointers | `ty-mismatch` | a struct array with a pointer field, or `u16` with `u16(&...)` |
| `str` struct fields | `ty-mismatch` | a `ptr<u8>` field |
| function addresses | `ty-not-lvalue` | none |
| a `const` holding an address | `ty-mismatch` | a global |
| calling an ASM export from C80 | `ty-unresolved-name` | call C80 from ASM instead |
| ordered pointer compares, pointer subtraction | `ty-mismatch` | compare `u16(p)` |
| interrupt handlers (no attribute exists) | `parse-expected` | an ASM unit |
| a register signature that does not fit | `cg-unsupported` | `@stackcall` |
| `asm` at file scope | `parse-unsupported` | an `asm` statement or an ASM unit |

```c80 error=parse-unsupported
u8 f(u8 x) { return x * 3; }
```

```c80 error=ty-recursion
u8 down(u8 n) { if (n == 0) { return 0; } return down(n - 1); }
```

```c80 error=ty-mismatch
struct P { u8 x; u8 y; };
u8 f(P p) { return p.x; }
```

```c80 error=ty-not-lvalue
u8 a[2];
u8 b[2];
void f() { a = b; }
```

```c80 error=ty-mismatch
ptr<u8> table[2];
```

```c80 error=ty-not-lvalue
u8 id(u8 x) { return x; }
u16 f() { return u16(&id); }
```

```c80 error=parse-expected
@interrupt void tick() { }
```

There is also no heap, no implicit promotion, no ROM wrapper, no
`--emit-map` file, no source-level debugger view, and no editor.

### Diagnostic codes

Each diagnostic has a severity, a stable code, a message, a primary span,
and optional related spans. Errors stop code generation; `ty-return-local-addr`
and some `ln-stack` reports are warnings. A use-before-assignment or an
unresolved name is reported once per local or name and function, with a
count of the further uses.

| Code | Meaning | Usual fix |
| --- | --- | --- |
| `lex-unexpected-character` | a character that starts no token | remove it |
| `lex-invalid-identifier` | non-ASCII in an identifier | ASCII names only |
| `lex-unterminated-block-comment` | `/*` without `*/` | close the comment |
| `lex-unterminated-string` | `"` without its end on the line | close the string |
| `lex-unterminated-char` | `'` without its end | close the literal |
| `lex-invalid-escape` | an escape outside the list above | `\xNN` |
| `lex-malformed-literal` | bad digits, `0x` without digits, non-ASCII in a literal | fix the literal |
| `lex-integer-overflow` | literal above 32 bits | smaller literal |
| `parse-expected` | missing or unexpected token; attribute misuse (unknown attribute, conflicting conventions, `@inline @stackcall`, `@preserves` misuse, misplaced `static` or pin) | follow the message |
| `parse-incomplete` | unclosed block, struct, or `asm` | close it |
| `parse-unsupported` | `*` `/` `%` and their compounds; file-scope `asm` | shifts and adds; move the `asm` |
| `ty-mismatch` | wrong type, unsupported type use, non-constant static initializer, local array, by-value aggregate, `break` outside a loop, wrong builtin arity | convert, use `static`, pass a pointer |
| `ty-literal-range` | a literal that does not fit, constant index outside an array, array or struct over 65535 bytes, a project value that is not a `u16` | smaller value or type |
| `ty-duplicate-name` | duplicate name, field, parameter, or import; overlapping pins; an inlined pin that collides at the call; label collisions | rename or re-pin |
| `ty-unresolved-name` | unknown name, type, unit, builtin; missing import; private cross-unit name | declare, import, or make it `pub` |
| `ty-not-lvalue` | assignment or `&` of something without an address (constant, function, payload, pinned local, whole array) | assign elements; drop the pin |
| `ty-use-before-assign` | a local read before every path assigns it | initialize it |
| `ty-missing-return` | a non-`void` path without a value | add `return` |
| `ty-recursion` | a cycle in the call graph | loop instead |
| `ty-invalid-conversion` | a conversion between incompatible types | convert via `u16` |
| `ty-void-value` | `void` used as a value or parameter type; `sizeof(void)` | use a value type |
| `ty-assign-const` | a write to a `const`, a `str` payload, or an owned `str` | use a variable |
| `ty-return-local-addr` | warning: returning `&local` | use a `static` or a global |
| `cg-unsupported` | code generation cannot meet the source's demands: a signature that does not fit, a pin or `@preserves` conflict, a strict `@fastcall` fallback, an invalid inline `asm` body, a marker in `asm` | follow the message |
| `cg-internal` | a compiler guard fired (for example a live value would be overwritten) | report it; it is a compiler bug |
| `ln-overlap` | two ranges overlap or pass 65536 | move an origin |
| `ln-missing-origin` | a unit emits bytes without an origin; `[basic]` without BASIC source | add `origin` |
| `ln-stack` | known stack use above `[stack].size` (error); unknown `asm` or ASM bounds (warning) | raise the size, add `stack:N` or `stack_extra` |

## Library Entry

```rust
let result = rtvc_c80::compile_source("unit.c80", source);
```

- `compile(CompileInput { files, origin, optimize, target })` compiles
  several in-memory files as one namespace; `compile_keeping_bodies` also
  emits fully inlined bodies.
- `project::compile_project(manifest, units, basic_source)` links a
  manifest; `compile_project_opt` takes the optimize flag and
  `compile_project_keeping_bodies` keeps inlined bodies.
- The result owns the source text, diagnostics, parsed units, optional typed
  IR (`program`), optional assembled code (`code`), and optional tokenized
  BASIC. Any error leaves `program` and `code` as `None`.
- `harness::execute_function` runs one generated function on a bounded Z80
  with flat memory; exceeding the instruction or T-state limit is a failure.
